# Halfcourt Tactics — 產品規格書 (v0.13)

> 3v3 半場籃球戰術 Web 小遊戲。使用者設計一方的戰術，系統模擬另一方，並評估結果。
> 技術：TypeScript + Vite + 原生 Canvas 2D，PWA。

---

## 1. 產品定位

介於「戰術板」與「遊戲」之間。**使用者固定操作藍隊，系統固定操作紅隊**；由模式決定哪一隊進攻。

| 模式 | 狀態 | 藍隊（使用者） | 紅隊（系統） | 結果 |
|---|---|---|---|---|
| **進攻模式** | **v1 先做** | 進攻：選內建戰術或自己畫跑位、傳球、運球、掩護、投籃 | 防守 AI 依對位即時反應 | 評等、預期得分、戰術評價 |
| **防守模式** | **暫緩**（首頁顯示「即將推出」） | 防守：看著紅隊的進攻路線，逐分鏡畫出防守反應 | 照劇本執行內建進攻戰術 | 評等、預期失分、戰術評價 |

- 原本的「自由模式」（兩隊都手動畫）**移除**。
- 單一回合，不計比賽總分、不做連續多回合。
- 模擬**沒有隨機性**：只輸出期望值、評等與文字評價，不判定投籃是否命中。

### 1.1 進攻模式流程

```
首頁：選模式 → ① 藍隊球員資料 → ② 紅隊球員資料 → ③ 對位設定 → 戰術面板
```

| 步驟 | 內容 | 按鈕 |
|---|---|---|
| 首頁 | 「進攻模式」「防守模式（即將推出，不能點）」 | — |
| ① 藍隊 | 三名球員：號碼、暱稱、身高、外線投射、速度、禁區終結、單打（§3.1） | 上一步 / **略過** / 下一步 |
| ② 紅隊 | 三名球員：號碼、暱稱、身高（§3.2） | 上一步 / **略過** / 下一步 |
| ③ 對位 | 預設對位 + 使用者調整（§6.2）；掩護應對（換防 / 擠過，預設換防） | 上一步 / 開始 |
| 戰術面板 | 戰術庫與推薦（§6.3）、自行畫戰術、播放 | 上方「球隊設定」按鈕可回來修改 |

- **略過** = 這一步全部使用預設值，直接到下一步。之後仍可從戰術面板回來修改。
- **從戰術面板回來修改時**：不再是 1 → 2 → 3 的流程，改成「藍隊 / 紅隊 / 對位」三個分頁，可以直接切換；底部只有「完成」，**沒有「略過」**（避免把設定好的資料清回預設值）。切換分頁或按完成時會先驗證並儲存目前這頁。
- 步驟頁上方顯示進度（1 / 3、2 / 3、3 / 3）。

## 2. 球場

- **FIBA 半場**，世界座標單位為公尺，原點在底線中點，x 向右、y 朝中場。
- 可視範圍：寬 15 m（x ∈ [-7.5, 7.5]）× 深 14 m（y ∈ [0, 14]），外加約 0.8 m 的場外邊距。
- **籃框在畫面下方，不可翻轉。**

| 元素 | 尺寸 (m) |
|---|---|
| 籃框中心 | 距底線 1.575 |
| 籃板 | 距底線 1.2，寬 1.8 |
| 禁區 | 寬 4.9 × 深 5.8 |
| 罰球圈 | 半徑 1.8（禁區內那半邊用虛線） |
| 合理衝撞區 | 半徑 1.25（以籃框中心為圓心） |
| 三分線 | 半徑 6.75；底角直線距離邊線 0.9 |
| 中圈 | 半徑 1.8，只畫出靠本場的一半 |

## 3. 場上物件

### 3.1 藍隊球員（使用者，3 名）
| 欄位 | 必填 | 說明 | 預設 |
|---|---|---|---|
| 號碼 | ✅ | 0–99，同隊不可重複 | 1、2、3 |
| 暱稱 | ✅ | 1–12 字，顯示在圓標下方 | 球員 1、球員 2、球員 3 |
| 身高 (cm) | 選填 | 150–230 | 空白（模型使用 175） |
| 外線投射 | ✅ | 優勢 / 稍強 / 平均 / 稍弱 / 劣勢 | 平均 |
| 速度 | ✅ | 優勢 / 稍強 / 平均 / 稍弱 / 劣勢 | 平均 |
| 禁區終結 | ✅ | 優勢 / 稍強 / 平均 / 稍弱 / 劣勢 | 平均 |
| 單打 | ✅ | 優勢 / 稍強 / 平均 / 稍弱 / 劣勢 | 平均 |

- **能力是相對值，以場上六個人的平均為基準。** 「外線投射優勢」= 這位球員的投籃比場上的平均好很多。兩隊用同一個基準，換防後也不會說不通。
- 「位置」與「體重」欄位**移除**：位置由四項能力取代；體重原本影響的速度改由「速度」能力決定，掩護與低位的效果改看身高差。
- **資料完整**（才會出現戰術推薦，§6.3）= 藍隊步驟沒有略過，而且三人都填了身高。其他欄位都有預設值，所以不算在內。

### 3.2 紅隊球員（系統，3 名）
| 欄位 | 必填 | 說明 | 預設 |
|---|---|---|---|
| 號碼 | ✅ | 0–99，同隊不可重複 | 1、2、3 |
| 暱稱 | ✅ | 1–12 字 | 對手 1、對手 2、對手 3 |
| 身高 (cm) | 選填 | 150–230 | 藍隊同順序球員的身高（藍隊沒填則空白） |
| 速度 | ✅ | 優勢 / 稍強 / 平均 / 稍弱 / 劣勢（以場上六個人的平均為基準） | 平均 |

- 紅隊只有速度一項等級；外線、禁區、單打是進攻能力，紅隊在 v1 只負責防守，用不到。
- 藍隊能力和紅隊速度用同一組等級、同一個基準，可以直接相比：兩邊都是「平均」時一樣快。

### 3.3 編輯與顯示
- 戰術面板上點擊球員，會開啟該隊的設定頁並跳到該球員。
- 身高留空時，即時顯示模型使用的值，以及換算後的跑動與運球速度。

### 3.4 球
- 獨立物件，可以單獨拖曳。
- 拖曳到球員附近（0.6 m 內）時會吸附，成為該球員的持球狀態。
- 任何時刻只有一顆球，也只有一位持球者（或球在空中）。

### 3.5 掩護標記
- 以「路線種類」的形式存在（見 §4）：跑位線的終點畫成 T 字，代表球員在該點設立掩護。

## 4. 路線

| 種類 | 樣式 | 意義 |
|---|---|---|
| 跑位 | 實線 + 箭頭 | 無球移動 |
| 運球 | 波浪線 + 箭頭 | 持球者移動，球跟著移動 |
| 傳球 | 虛線 + 箭頭 | 球從 A 飛到 B，起點必須是持球者，終點必須是隊友 |
| 掩護 | 實線 + T 字端點 | 移動到終點後設立掩護 |
| 投籃 | 點狀弧線 + 籃框外的目標圈 | 持球者出手，**回合結束**。只能在最後一個分鏡；點持球者即建立，不用拖線，弧線自動產生、不能編輯 |

- **繪製方式**：
  - **預設（平滑）**：拖出起點到終點，途中可以點選控制點，系統自動用 Catmull-Rom 平滑成曲線。
  - **手繪**：切換成手繪模式後，記錄手指軌跡，用 RDP 演算法簡化點數（容差 0.1 m）後再做平滑。
- 進攻模式下只能畫**藍隊**的路線；紅隊的移動由防守 AI 產生，不能畫、不能拖曳。
- 每位球員在每個分鏡最多一條路線；畫新的路線會取代舊的。
- 路線的起點永遠跟著球員：分鏡開始時的位置被拖走，路線起點也跟著移動。
- **傳球**：傳球者在同一個分鏡不能同時移動（因為一人只有一條路線）；傳球終點指向接球者在本分鏡**結束時**的位置，接球者改變跑位時會自動跟著改。
- 球換人持有時，舊持球者的運球、傳球與投籃路線會自動移除，並提示使用者。
- 已經投籃時，不能在最後一個分鏡後面新增分鏡（可以在前面插入）。
- 移動路線的終點會顯示該球員的半透明分身。

### 4.1 編輯操作
| 操作 | 方式 |
|---|---|
| 選工具 | 下方工具按鈕開啟選單：移動 / 跑位 / 運球 / 傳球 / 掩護 / 投籃，以及「手繪」開關 |
| 畫線 | 選好路線種類後，從球員（或球）拖出去；太短（< 0.6 m）視為誤觸 |
| 選取路線 | 點路線本身 |
| 加彎 | 選取後，拖曳兩個控制點中間的「＋」把手，會插入新的控制點 |
| 移動控制點 | 拖曳白色圓點（起點固定在球員身上；傳球終點固定在接球者身上） |
| 刪除控制點 | 點一下中間的白色圓點 |
| 刪除路線 | 選取後按刪除鍵或垃圾桶 |
| 鍵盤（桌機） | V 移動、1 跑位、2 運球、3 傳球、4 掩護、5 投籃、F 手繪、Del 刪除、Esc 取消、⌘/Ctrl+Z 復原、⇧⌘Z / Ctrl+Y 重做 |

## 5. 分鏡與播放

- 一個戰術由 **N 個分鏡** 組成，**1 ≤ N ≤ 12**。
- 每個分鏡保存：「分鏡開始時所有物件的位置」加上「本分鏡的所有路線」。
  下一個分鏡的起始位置 = 上一分鏡路線的終點（自動帶入）。
- **播放**：按下播放後，從第一個分鏡完整播到最後一個分鏡，v1 不做暫停、調速、逐步播放。
  - 球員依路線移動，速度由 §7 的速度模型決定，所以不同球員會有先後抵達的差異。
  - 傳球：球沿著傳球線飛行，速度 12 m/s。**不做抄截。**
  - 分鏡內所有移動都結束後，才進入下一個分鏡。
- **站位鎖定**：只有第 1 個分鏡可以拖曳藍隊球員與球（紅隊站位由防守 AI 依對位決定）；之後分鏡的站位與持球者都由上一個分鏡推算（傳球後由接球者持球），只能畫路線。改動前面的分鏡時，後面分鏡會自動更新，不再成立的路線會被移除並提示。
- **掩護者先站住**：上一個分鏡設了掩護的人，這個分鏡先在原地站 0.5 秒才開始移動（等持球者利用掩護後才下順或外彈）。
- **分鏡內的時間**：所有球員同時出發；傳球的出手時間讓球剛好在接球者跑到終點時抵達（接球者不動則立刻出手）。沒有任何移動的分鏡停留 0.5 秒。
- **分鏡操作**：「‹ ›」切換、「＋」在目前分鏡後面新增、點「n / N」開選單刪除目前分鏡。新增、刪除都算一步，可以復原。
- 球場上方顯示目前分鏡時長與總時間；超過 12 秒時變紅。
- **投籃**：分鏡一開始就出手，球沿弧線飛進籃框（水平速度 8 m/s，至少 0.5 秒）。
- **時長**：每個分鏡約 1–3 秒。**出手時間**（沒有投籃時為總時間）超過 **12 秒**（3x3 的進攻時限）時**顯示警告**，但仍然可以播放和存檔。評價中也會列出這一點（見 §6.5）。

## 6. 模擬引擎

### 6.1 原則
- 固定時間步長（1/60 s），**完全決定性**：同樣的輸入一定得到同樣的結果，所以分享連結可以重現同一個結果。
- 模擬邏輯要與繪圖分離（純 TS 模組，可以寫單元測試）。
- 所有係數集中在 `sim/config.ts`。

### 6.2 對位與防守 AI（紅隊防守）

**預設對位（步驟 ③）：**
- 藍隊三人**都有填身高** → 依身高排序配對：藍隊最高的對紅隊最高的，依此類推（紅隊用實際值或預設值；同高時維持原本順序）。
- 否則 → 依步驟 ①② 的順序配對（藍 1 對紅 1、藍 2 對紅 2、藍 3 對紅 3）。
- 使用者可以重新配置：點藍隊球員，再點要對位的紅隊球員，兩人交換對象。畫面同時顯示每組的身高差與速度差。

**防守 AI（人盯人）：**
- 每 1/60 秒更新一次。藍隊只照路線移動、不受紅隊影響，所以先算出藍隊的位置，再推進紅隊；完全決定性。
- **防守位置**：
  - 防持球者、防籃下附近（離籃框 4.5 m 以內）的無球者、防離持球者 3.5 m 以內（例如正在掩護）的無球者：在「對位球員與籃框的連線上」，防持球者 1.5 m、防無球者 2.0 m；對位者靠近籃框時退到兩人中間，但至少 1.45 m。圓標直徑約 1.44 m，距離比真實比賽略大，圓標才不會疊在一起。
  - **阻絕**：防外圍（離籃框超過 4.5 m）的無球者時，站到傳球路線上：對位者 + 往持球者方向 1.3 m + 往籃框方向 0.5 m。所以背切、傳切能打出空檔。
  - 球在空中（傳球飛行中）時不阻絕，退回人和籃框之間。
- **被甩開只能從後面追**：對位者擋在防守者和籃框之間（對位者比防守者更靠近籃框超過 0.3 m，而且從對位者看，防守者和籃框的夾角大於 120°）時，防守者穿不過去，改追在對位者身後；對位者往外走、或防守者回到側邊後恢復正常。只是往籃下走（例如要位）、防守者還在旁邊時，不算被甩開。
- **反應時間 0.2 秒**：防守者看到的是 0.2 秒前的場上狀況（包含傳球後誰持球）。
- **移動速度**：§7 的速度 × 0.9（側滑、倒退比衝刺慢）。所以防運球者只能慢慢追回、防空切會被甩開，追不上就是追不上。
- **身體碰撞**：防守者不能穿過進攻者，兩人中心至少相距 1.3 m。
- 第 2 個分鏡之後，編輯畫面上的紅隊位置 = 模擬中該分鏡開始時的實際位置（可能被甩開或還在換防）。
- 播放時，被掩護卡住的防守者外圍會亮黃色光暈。
- **掩護判定**：掩護者到位之後、離開掩護點 0.5 m 之前，若防守者中心離掩護者 1.4 m 以內，而且掩護者擋在他要去的方向上，就算被掩護到。每個掩護只觸發一次。
- **掩護應對**（步驟 ③ 選擇，**預設換防**）：
  - 換防：被掩護的防守者停住 0.3 秒，然後和掩護者的防守者交換對位；換防後可能形成身高錯位。
  - 擠過：被掩護的防守者停住 t 秒後繼續追原本的人；t = 0.45 + 0.015 ×（掩護者身高 − 防守者身高），介於 0.25–0.9 秒。
- 系統**不做**補防和區域聯防。

### 6.3 內建戰術庫與推薦

**戰術庫（18 套）：** 每套戰術是預先寫好的藍隊分鏡資料，定義三個角色；載入時依指派把角色換成實際球員。

| # | 戰術 | 角色 A（持球） | 角色 B | 角色 C | 終結 | 主要看的能力 |
|---|---|---|---|---|---|---|
| 1 | 高位擋拆-Pull-up Jumper | 持球者 | 掩護者 | 拉開 | A 擋拆後急停跳投 | A 外線、A 單打 |
| 2 | 高位擋拆-Floater | 持球者 | 掩護者 | 拉開 | A 切入拋投 | A 禁區終結、A 速度 |
| 3 | 高位擋拆-Drive to Rim | 持球者 | 掩護者 | 拉開 | A 切入上籃 | A 速度、A 禁區終結、A 單打 |
| 4 | 高位擋拆-Pick and Pop | 持球者 | 掩護者 | 拉開 | B 外彈接球投籃 | B 外線 |
| 5 | 高位擋拆-Pick and Roll | 持球者 | 掩護者 | 拉開 | B 下順接球上籃 | B 禁區終結、B 身高 |
| 6 | 低位擋拆-Paint Shot | 傳入低位後掩護 | 低位持球、禁區中路出手 | 拉開 | A 傳給 B 後幫 B 掩護，B 運到禁區中路出手 | B 禁區終結、B 單打 |
| 7 | 低位擋拆-Pick and Roll | 傳球後掩護、順下 | 低位持球者 | 拉開 | A 傳給 B 後幫 B 掩護並順下，B 回傳，A 上籃 | A 禁區終結、A 身高 |
| 8 | 空切-Pass and Cut | 傳球後空切 | 接球者 | 拉開 | A 切入接回傳上籃 | A 速度、A 禁區終結 |

| 12 | 無球掩護-Post Split | 傳入低位後掩護，再外彈投籃 | 低位傳球 | 回頭幫 A 掩護，再切入 | 交叉掩護（A、C 互相擋住對方的防守者），A 外彈接球投籃，C 切入為第二選擇 | A 外線、B 身高、C 禁區終結與速度 |
| 13 | 手遞手-DHO to Drive | 手遞手給球者 | 接球者 | 拉開 | B 接手遞手後繞過 A 往中路切入，A 擋住防守者 | B 速度、B 單打、B 禁區終結 |
| 14 | 手遞手-DHO to Shoot | 手遞手給球者 | 接球者 | 拉開 | B 接球後從 A 外側繞到弧頂，A 擋住防守者，B 投籃 | B 外線 |
| 15 | 手遞手-Fake Hand-Off | 假手遞手者 | 假接球者 | 拉開 | A 假遞後自己切入上籃；B 從 A 外側繞到弧頂，帶走防守者 | A 單打、A 禁區終結 |
| 16 | 單打-Top Isolation | 單打持球者 | 拉開 | 拉開 | B、C 拉到底角，A 弧頂一對一切入 | A 單打、A 禁區終結 |
| 17 | 單打-Post Isolation | 傳入低位 | 低位單打 | 拉開 | B 低位要位接球，A、C 拉開，B 轉身投籃 | B 身高、B 禁區終結、B 單打 |
| 18 | 單打-Hunting the Mismatch | 單打持球者 | 掩護者（引出錯位） | 拉開 | 擋拆逼換防，A 對錯位的防守者切入 | A 單打、A 速度 |

> 每套戰術的詳細跑位與分鏡圖見 `docs/PLAYS.md`（由 `npm run plays-doc` 從 `src/plays/library.ts` 產生）。

**推薦演算法（藍隊資料完整時才出現，§3.1）：**
1. 分數（0–4，平均 = 2）：
   - 外線投射、禁區終結、單打：直接用能力等級（優勢 = 4、稍強 = 3、平均 = 2、稍弱 = 1、劣勢 = 0）。
   - 身高、速度：跟步驟 ③ **對位的防守者**比。身高每差 5 cm 算一級、速度每差 5% 算一級（速度包含身高與雙方的速度等級），超過 0–4 就截斷。
2. 每套戰術的每個角色對各項有權重（`src/plays/library.ts` 的 `weights`，`docs/PLAYS.md` 的「推薦時看重」）。
3. 戰術分數 = Σ 權重 × 分數 ÷ Σ 權重，權重項目多的戰術不會因此佔便宜。三名球員分配到三個角色共 6 種排法，取分數最高的排法（同分取排列順序在前的）。
4. 18 套戰術依分數排序（同分維持戰術庫順序），列出**前 5 名**，並附一句理由（取貢獻最大的一項，例如「2 號外線投射優勢，適合外彈投籃」）。
5. 完全決定性：同樣的資料一定得到同樣的推薦。

**操作：**
- 戰術面板的「戰術庫」面板：上方是推薦（資料完整時），下方是全部 18 套（資料不完整時只顯示這部分，仍可點選播放）。
- 上方工具列第二個按鈕（書本圖示）開啟戰術庫。面板由上到下：
  1. **空白戰術**：清掉目前的跑位，回到預設站位自己畫；球員資料、對位與掩護應對保留。算一步，可以復原。
  2. **球隊總評**（資料完整時）：每人一行，列出強項（能力「稍強」以上、比對位者高 5 cm 以上、快 5% 以上）→ 適合的戰術類型（外線出手、切入或下順、持球單打、空切或切入、低位或下順）與最多 3 套例子；最後一句整體建議（主要攻擊點、第二選擇、最適合的戰術）。同強度時，以對應戰術在推薦中的名次排序，讓總評和推薦清單一致。
  3. **推薦給你的球隊**（資料完整時）前 5 名；資料不完整時改為提示「藍隊三人都填了身高，就會推薦」，並有按鈕直接前往設定。
  4. 全部戰術，依類別分組。
- 點擊戰術 → 依推薦的角色分配（從全部清單點選時，也自動找最佳分配）載入成分鏡，並**立刻自動播放一次**；紅隊依防守 AI 移動。載入算一步，可以按復原回到原本的戰術。
- 球場上方顯示目前的戰術名稱；修改過分鏡（路線、站位、分鏡數）後顯示「根據〈戰術名〉修改」。只改球員資料或對位不算修改。
- 載入後可以繼續修改藍隊的路線、增減分鏡，但**內建戰術本身永遠不會被改寫**：修改的是一份複本，畫面標示「根據〈戰術名〉修改」，要保留就另存成新的戰術（存檔在 M8）。再點一次同一套內建戰術，會重新載入原始版本。

### 6.4 評估與評等
- **評哪一球**：
  - 進攻模式：使用者有畫投籃，就評**這一球**，並在評價中列出「更好的出手選擇」（如果有）。沒有畫投籃也可以（不強制），系統改評最後一個分鏡中空檔程度最高的出手，並在評價中提醒「這套戰術沒有終結點」。
  - 防守模式（暫緩）：紅隊的內建戰術在最後一個分鏡由系統決定誰投。
- **空檔程度**：與最近防守者的距離，再依身高差修正（防守者比較高時，干擾範圍比較大）。
- **出手價值**：依區域（禁區 / 中距離 / 弧外）× 出手者的能力等級（§7.2）得出命中率，再乘上該區分數，得出預期得分（xPts）。
- **計分規則**：採 **FIBA 3x3**，弧內 1 分、弧外 2 分。
- **評等**（門檻為暫定值，可在 config 調整）：

| 評等 | 進攻模式：xPts | 防守模式：預期失分 |
|---|---|---|
| S | ≥ 0.80 | ≤ 0.45 |
| A | ≥ 0.70 | ≤ 0.55 |
| B | ≥ 0.60 | ≤ 0.65 |
| C | ≥ 0.50 | ≤ 0.75 |
| D | < 0.50 | > 0.75 |

> 參考：空檔時，外線優勢的弧外投籃 ≈ 0.84、禁區終結優勢的上籃 ≈ 0.70、平均球員的中距離 ≈ 0.40。

### 6.5 戰術評價（文字）
播放結束後顯示「評等 + 期望值 + 3～5 條評價」，每條都指向具體的分鏡和球員，點擊後跳到該分鏡，並在場上標示位置。評價由規則產生：

| 類型 | 範例 |
|---|---|
| 最佳出手 | 「第 4 分鏡，球員 3 在右底角空檔 2.4 m，預期得分 1.18」 |
| 掩護成效 | 「第 2 分鏡的掩護讓防守者延遲 0.6 秒」／「掩護太早，防守者已經繞過」 |
| 空間配置 | 「第 3 分鏡，球員 2 和球員 4 距離不到 3 m，擠壓了切入空間」 |
| 對位優勢 | 「換防後形成 球員 5（C）對 球員 1（PG）的錯位，低位有 +18 cm 的身高優勢」 |
| 時間 | 「第 13.2 秒才出手，超過 12 秒進攻時限」 |
| 終結點 | 「這套戰術沒有投籃，系統以球員 3 的底角三分評分」／「球員 2 的出手被干擾，其實球員 3 在弧頂更空」 |
| 防守漏洞（防守模式） | 「第 3 分鏡沒有補防，禁區完全空出」 |

## 7. 球員能力模型

> 以下係數都是暫定值，集中在 `sim/config.ts`，M7 實際跑出結果後再校正。
> 等級：優勢 / 稍強 / 平均 / 稍弱 / 劣勢（分數 4 → 0），以場上六個人的平均為基準；藍隊四項能力與紅隊速度共用。

### 7.1 速度
```
base = 5.0 m/s（無球跑動）
運球 ×0.85
身高 = clamp(1 - 0.003·(身高-175), 0.92, 1.08)      兩隊都適用，紅隊的身高因此仍有作用；175 cm = 1.00
速度等級 = 4: 1.10 / 3: 1.05 / 2: 1.00 / 1: 0.95 / 0: 0.90     藍隊看能力的「速度」，紅隊看自己的「速度」
speed = base × 身高 × 能力
```

### 7.2 能力等級的作用
| 能力 | 作用 | 優勢 / 稍強 / 平均 / 稍弱 / 劣勢（暫定） |
|---|---|---|
| 外線投射 | 弧外（2 分）與中距離（1 分）的空檔命中率 | 弧外 42 / 37 / 33 / 28 / 23 %；中距離 50 / 45 / 40 / 35 / 30 % |
| 速度 | 跑動與運球速度（§7.1） | ×1.10 / 1.05 / 1.00 / 0.95 / 0.90 |
| 禁區終結 | 禁區（含拋投，1 分）的空檔命中率 | 70 / 62 / 55 / 48 / 40 % |
| 單打 | 運球切入或急停時，與對位者拉開的距離 | +0.60 / 0.45 / 0.30 / 0.15 / 0 m |

- 有人防守時，命中率依空檔程度往下修正（§6.4）。

### 7.3 對位優勢
- **身高差** → 出手時受到的干擾、傳球的干擾範圍、掩護的效果、低位單打的效果。
- **速度差** → 切入時能不能甩開對位者。
- 對位設定頁顯示每組的差異（例如「身高 +8cm / 速度 −5%」）。

### 7.4 未填時的預設值
- 藍隊：身高 175 cm。
- 紅隊：藍隊同順序球員的身高；藍隊也沒填則 175 cm。

## 8. 存檔與分享

- **戰術必須命名**（1–30 字），存檔時如果沒有名稱會要求輸入。
- **localStorage**：保存戰術列表（名稱、模式、評等、更新時間），可以開啟、重新命名、複製、刪除。
- **JSON**：可以匯出和匯入單一戰術檔。匯入的資料要檢查 schema 版本並驗證內容。
- **分享連結**：`https://…/#p=<base64url(deflate-raw(JSON))>`
  - 座標四捨五入到公分，手繪路線先簡化再存，以壓縮網址長度。
  - 開啟分享連結時進入唯讀預覽，按「另存」後才寫入 localStorage。
- 資料要帶 `version` 欄位，方便之後遷移格式。

## 9. 編輯操作

- 復原 / 重做：**最多 5 步**。每一步是一次完整操作：拖曳放開、完成一條線、送出編輯。
- 刪除：先選取物件，再按刪除（球員不能刪除，只能刪除路線）。
- 編輯中切換分鏡時，歷史紀錄不清空。

## 10. 版面與平台

- **直式**：上方工具列 / 球場 / 下方工具列（參照 `example.jpg`）。
- **橫式**：球場置中，工具列移到左右兩側；籃框仍然在球場的下方。
- 不支援縮放和平移。
- 高解析度螢幕：canvas 依 `devicePixelRatio` 縮放。
- 觸控與滑鼠統一使用 Pointer Events，canvas 設定 `touch-action: none`。
- **PWA**：使用 `vite-plugin-pwa`，可以離線使用、加到主畫面。
- 介面語言：只做繁體中文（文字集中管理，方便之後加入 i18n）。
- **按鈕提示**：滑鼠移到工具列、分鏡列的按鈕上約 0.3 秒，顯示按鈕用途與快捷鍵（停用的按鈕顯示「即將推出」）；橫式時，左右兩側工具列的提示分別出現在按鈕右邊、左邊。觸控裝置沒有 hover，不顯示。

## 11. 資料模型（草案）

```ts
type Team = 'blue' | 'red';                     // blue = 使用者，red = 系統
type Mode = 'offense' | 'defense';
type Rating = 0 | 1 | 2 | 3 | 4;   // 劣勢 / 稍弱 / 平均 / 稍強 / 優勢（以場上六個人的平均為基準）
type Vec2 = { x: number; y: number };           // 公尺

interface Skills {
  shooting: Rating;   // 外線投射
  speed: Rating;      // 速度
  finishing: Rating;  // 禁區終結
  iso: Rating;        // 單打
}

interface Player {
  id: string;             // 'b1'..'b3', 'r1'..'r3'
  team: Team;
  number: number;
  name: string;           // 暱稱
  heightCm?: number;
  skills?: Skills;        // 只有藍隊
  speedRating?: Rating;   // 只有紅隊，未填 = 平均
}

type PathKind = 'cut' | 'dribble' | 'pass' | 'screen' | 'shot';

interface TacticPath {
  id: string;
  kind: PathKind;
  actorId: string;        // 傳球時為傳球者
  targetId?: string;      // 傳球時為接球者
  points: Vec2[];         // 控制點（已簡化）
  freehand: boolean;
}

interface Frame {
  start: Record<string, Vec2>;   // playerId / 'ball' → 位置（紅隊由防守 AI 推算）
  ballHolderId: string | null;
  paths: TacticPath[];           // 只有藍隊的路線
}

interface Tactic {
  version: 1;
  id: string;
  name: string;
  mode: Mode;
  setup: { blueSkipped: boolean; redSkipped: boolean };
  matchups: Record<string, string>;            // 藍隊 id → 紅隊 id
  screenDefense: 'fight-over' | 'switch';
  basedOn?: { playId: string; roles: Record<'A' | 'B' | 'C', string>; modified: boolean };  // 從戰術庫載入時
  players: Player[];
  frames: Frame[];
  lastResult?: { grade: 'S' | 'A' | 'B' | 'C' | 'D'; expectedPoints: number };
  updatedAt: number;
}
```
