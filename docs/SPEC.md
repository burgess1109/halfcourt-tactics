# Halfcourt Tactics — 產品規格書 (v0.4)

> 3v3 半場籃球戰術 Web 小遊戲。使用者設計一方的戰術，系統模擬另一方，並評估結果。
> 技術：TypeScript + Vite + 原生 Canvas 2D，PWA。

---

## 1. 產品定位

介於「戰術板」與「遊戲」之間。**使用者固定操作藍隊，系統固定操作紅隊**；由模式決定哪一隊進攻。

| 模式 | 藍隊（使用者） | 紅隊（系統） | 結果 |
|---|---|---|---|
| **進攻設計** | 進攻：擺位，並畫跑位、傳球、運球、掩護 | 防守 AI 即時反應 | 評等、預期得分、戰術評價 |
| **防守設計** | 防守：先選一套紅隊進攻戰術，看著紅隊的路線，逐分鏡畫出防守反應（包含補防、區域聯防） | 照劇本執行內建進攻戰術 | 評等、預期失分、戰術評價 |
| **自由模式** | 使用者手動操作兩隊 | 無 | 純戰術板，只播放，不評分 |

- 單一回合，不計比賽總分、不做連續多回合。
- 模擬**沒有隨機性**：只輸出期望值、評等與文字評價，不判定投籃是否命中。

## 2. 球場

- **FIBA 半場**，世界座標單位為公尺，原點在底線中點，x 向右、y 朝中場。
- 可視範圍：寬 15 m（x ∈ [-7.5, 7.5]）× 深 14 m（y ∈ [0, 14]），外加約 0.8 m 的場外邊距。
- **籃框在畫面下方，不可翻轉。**

| 元素 | 尺寸 (m) |
|---|---|
| 籃框中心 | 距底線 1.575 |
| 籃板 | 距底線 1.2，寬 1.8 |
| 禁區 | 寬 4.9 × 深 5.8 |
| 罰球圈 | 半徑 1.8（禁區內那半邊用虛線） |
| 合理衝撞區 | 半徑 1.25（以籃框中心為圓心） |
| 三分線 | 半徑 6.75；底角直線距離邊線 0.9 |
| 中圈 | 半徑 1.8，只畫出靠本場的一半 |

## 3. 場上物件

### 3.1 球員（固定 3 藍 3 紅）
| 欄位 | 必填 | 說明 |
|---|---|---|
| 號碼 | ✅ | 0–99，顯示在圓標內 |
| 名字 | ✅ | 顯示在圓標下方，預設為「球員 N」 |
| 位置 | 選填 | PG / SG / SF / PF / C，**允許重複**（如 SF/SF/SF） |
| 身高 (cm) | 選填 | 150–230 |
| 體重 (kg) | 選填 | 50–150 |

- 點擊球員即可開啟編輯面板。紅隊球員也可以編輯，用來設定對手的體型。
- 身高、體重未填時的預設值見 §7.3。

### 3.2 球
- 獨立物件，可以單獨拖曳。
- 拖曳到球員附近（0.6 m 內）時會吸附，成為該球員的持球狀態。
- 任何時刻只有一顆球，也只有一位持球者（或球在空中）。

### 3.3 掩護標記
- 以「路線種類」的形式存在（見 §4）：跑位線的終點畫成 T 字，代表球員在該點設立掩護。

## 4. 路線

| 種類 | 樣式 | 意義 |
|---|---|---|
| 跑位 | 實線 + 箭頭 | 無球移動（防守方的移動也用這種） |
| 運球 | 波浪線 + 箭頭 | 持球者移動，球跟著移動 |
| 傳球 | 虛線 + 箭頭 | 球從 A 飛到 B，起點必須是持球者，終點必須是隊友 |
| 掩護 | 實線 + T 字端點 | 移動到終點後設立掩護 |

- **繪製方式**：
  - **預設（平滑）**：拖出起點到終點，途中可以點選控制點，系統自動用 Catmull-Rom 平滑成曲線。
  - **手繪**：切換成手繪模式後，記錄手指軌跡，用 RDP 演算法簡化點數（容差 0.1 m）後再做平滑。
- 每位球員在每個分鏡最多一條路線；畫新的路線會取代舊的。
- 路線的起點永遠跟著球員：分鏡開始時的位置被拖走，路線起點也跟著移動。
- **傳球**：傳球者在同一個分鏡不能同時移動（因為一人只有一條路線）；傳球終點指向接球者在本分鏡**結束時**的位置，接球者改變跑位時會自動跟著改。
- 球換人持有時，舊持球者的運球與傳球路線會自動移除，並提示使用者。
- 移動路線的終點會顯示該球員的半透明分身。

### 4.1 編輯操作
| 操作 | 方式 |
|---|---|
| 選工具 | 下方工具按鈕開啟選單：移動 / 跑位 / 運球 / 傳球 / 掩護，以及「手繪」開關 |
| 畫線 | 選好路線種類後，從球員（或球）拖出去；太短（< 0.6 m）視為誤觸 |
| 選取路線 | 點路線本身 |
| 加彎 | 選取後，拖曳兩個控制點中間的「＋」把手，會插入新的控制點 |
| 移動控制點 | 拖曳白色圓點（起點固定在球員身上；傳球終點固定在接球者身上） |
| 刪除控制點 | 點一下中間的白色圓點 |
| 刪除路線 | 選取後按刪除鍵或垃圾桶 |
| 鍵盤（桌機） | V 移動、1 跑位、2 運球、3 傳球、4 掩護、F 手繪、Del 刪除、Esc 取消、⌘/Ctrl+Z 復原、⇧⌘Z / Ctrl+Y 重做 |

## 5. 分鏡與播放

- 一個戰術由 **N 個分鏡** 組成，**1 ≤ N ≤ 12**。
- 防守設計模式的分鏡數量由選定的進攻戰術決定，使用者不能新增或刪除分鏡。
- 每個分鏡保存：「分鏡開始時所有物件的位置」加上「本分鏡的所有路線」。
  下一個分鏡的起始位置 = 上一分鏡路線的終點（自動帶入）。
- **播放**：按下播放後，從第一個分鏡完整播到最後一個分鏡，v1 不做暫停、調速、逐步播放。
  - 球員依路線移動，速度由 §7 的速度模型決定，所以不同球員會有先後抵達的差異。
  - 傳球：球沿著傳球線飛行，速度 12 m/s。**不做抄截。**
  - 分鏡內所有移動都結束後，才進入下一個分鏡。
- **時長**：每個分鏡約 1–3 秒。整個戰術超過 **12 秒**（3x3 的進攻時限）時**顯示警告**，但仍然可以播放和存檔。評價中也會列出這一點（見 §6.5）。

## 6. 模擬引擎

### 6.1 原則
- 固定時間步長（1/60 s），**完全決定性**：同樣的輸入一定得到同樣的結果，所以分享連結可以重現同一個結果。
- 模擬邏輯要與繪圖分離（純 TS 模組，可以寫單元測試）。
- 所有係數集中在 `sim/config.ts`。

### 6.2 防守 AI（進攻設計模式，紅隊防守）
- **人盯人**：每位防守者對位一位進攻者。**由使用者手動指定對位**：進入模式時先依起始位置最近配對作為預設，使用者可以在「對位」面板中修改，也可以直接在場上拖線連接兩位球員。防守者的位置在「對位球員與籃框的連線上」，距離依對位球員與籃框的距離、以及是否持球調整。
- **掩護應對**：使用者在開始前選擇 **擠過（fight over）** 或 **換防（switch）**。
  - 擠過：被掩護的防守者路徑經過掩護者 0.8 m 範圍內時，會延遲 t 秒；t 由雙方體重差決定。
  - 換防：掩護者的防守者和被掩護者的防守者交換對位，交換過程有短暫的反應延遲。
- 系統**不做**補防和區域聯防，這兩種只出現在防守設計模式，由使用者自行畫出。
- 防守者也使用 §7 的速度模型，追不上就是追不上。

### 6.3 進攻 AI（防守設計模式，紅隊進攻）

**流程（防守解題）：**
1. 從戰術庫選一套紅隊進攻戰術。
2. 紅隊的站位與每個分鏡的路線都會顯示在場上，並用半透明預覽。
3. 使用者擺好藍隊的起始站位，逐分鏡畫出藍隊的防守移動。
4. 按下播放：紅隊照劇本執行，藍隊照使用者畫的路線移動，兩隊都套用 §7 的速度模型。
5. 評估紅隊在最後一個分鏡的出手機會，並給出評等與評價。

- 紅隊**不會**因為藍隊的站位而改變路線（固定劇本）。唯一的反應是最後一個分鏡由空檔程度最高的球員出手。

內建 **10 套**常見的 3v3 進攻戰術。M6 先做前 5 套，後 5 套在 M6b 補齊。

| # | 戰術 | 批次 |
|---|---|---|
| 1 | 擋拆（Pick & Roll） | M6 |
| 2 | 手遞手（Dribble Hand-Off） | M6 |
| 3 | 傳切（Give & Go） | M6 |
| 4 | 背門空切（Backdoor Cut） | M6 |
| 5 | 單打（Isolation） | M6 |
| 6 | 擋拆外彈（Pick & Pop） | M6b |
| 7 | 下掩護（Down Screen） | M6b |
| 8 | 西班牙擋拆（Spanish P&R） | M6b |
| 9 | 牛角（Horns） | M6b |
| 10 | 低位單打（Post-Up） | M6b |

- 每套戰術都是預先寫好的分鏡資料（紅隊的路線），和使用者存的戰術格式相同。
- 播到最後一個分鏡時，把球交給**當下空檔程度最高**的隊友出手。

### 6.4 評估與評等
- **空檔程度**：與最近防守者的距離，再依身高差修正（防守者比較高時，干擾範圍比較大）。
- **出手價值**：依區域（禁區 / 中距離 / 三分）乘上命中率基準值，得出預期得分（xPts）。
- **評等**（門檻為暫定值，可在 config 調整）：

| 評等 | 進攻設計：xPts | 防守設計：預期失分 |
|---|---|---|
| S | ≥ 1.25 | ≤ 0.70 |
| A | ≥ 1.10 | ≤ 0.85 |
| B | ≥ 0.95 | ≤ 1.00 |
| C | ≥ 0.80 | ≤ 1.15 |
| D | < 0.80 | > 1.15 |

### 6.5 戰術評價（文字）
播放結束後顯示「評等 + 期望值 + 3～5 條評價」，每條都指向具體的分鏡和球員，點擊後跳到該分鏡，並在場上標示位置。評價由規則產生：

| 類型 | 範例 |
|---|---|
| 最佳出手 | 「第 4 分鏡，球員 3 在右底角空檔 2.4 m，預期得分 1.18」 |
| 掩護成效 | 「第 2 分鏡的掩護讓防守者延遲 0.6 秒」／「掩護太早，防守者已經繞過」 |
| 空間配置 | 「第 3 分鏡，球員 2 和球員 4 距離不到 3 m，擠壓了切入空間」 |
| 對位優勢 | 「換防後形成 球員 5（C）對 球員 1（PG）的錯位，低位有 +18 cm 的身高優勢」 |
| 時間 | 「整個戰術耗時 13.2 秒，超過 12 秒進攻時限」 |
| 防守漏洞（防守設計） | 「第 3 分鏡沒有補防，禁區完全空出」 |

## 7. 身高體重模型

### 7.1 速度
```
base = 5.0 m/s（無球跑動）
運球 ×0.85
factor = clamp(1 - 0.004·(身高-195) - 0.003·(體重-90), 0.85, 1.15)
speed = base × factor
```

### 7.2 對位優勢
- **身高差** → 影響出手時受到的干擾，以及傳球時的干擾範圍。
- **速度差** → 影響切入時能不能甩開對位者。
- **體重差** → 影響掩護的延遲時間，以及低位單打的效果。
- 編輯球員時即時顯示對位差異（例如「身高 +8cm / 速度 −5%」）。

### 7.3 未填時的預設值
| 位置 | 身高 | 體重 |
|---|---|---|
| PG | 185 | 80 |
| SG | 193 | 88 |
| SF | 201 | 98 |
| PF | 206 | 108 |
| C | 211 | 115 |
| 未填位置 | 198 | 95 |

## 8. 存檔與分享

- **戰術必須命名**（1–30 字），存檔時如果沒有名稱會要求輸入。
- **localStorage**：保存戰術列表（名稱、模式、評等、更新時間），可以開啟、重新命名、複製、刪除。
- **JSON**：可以匯出和匯入單一戰術檔。匯入的資料要檢查 schema 版本並驗證內容。
- **分享連結**：`https://…/#p=<base64url(deflate-raw(JSON))>`
  - 座標四捨五入到公分，手繪路線先簡化再存，以壓縮網址長度。
  - 開啟分享連結時進入唯讀預覽，按「另存」後才寫入 localStorage。
- 資料要帶 `version` 欄位，方便之後遷移格式。

---

## 9. 編輯操作

- 復原 / 重做：**最多 5 步**。每一步是一次完整操作：拖曳放開、完成一條線、送出編輯。
- 刪除：先選取物件，再按刪除（球員不能刪除，只能刪除路線）。
- 編輯中切換分鏡時，歷史紀錄不清空。

## 10. 版面與平台

- **直式**：上方工具列 / 球場 / 下方工具列（參照 `example.jpg`）。
- **橫式**：球場置中，工具列移到左右兩側；籃框仍然在球場的下方。
- 不支援縮放和平移。
- 高解析度螢幕：canvas 依 `devicePixelRatio` 縮放。
- 觸控與滑鼠統一使用 Pointer Events，canvas 設定 `touch-action: none`。
- **PWA**：使用 `vite-plugin-pwa`，可以離線使用、加到主畫面。
- 介面語言：只做繁體中文（文字集中管理，方便之後加入 i18n）。

### 10.1 工具列（對照 example.jpg）
| 位置 | 按鈕 |
|---|---|
| 上方 | 戰術列表、播放、模式 / 防守策略 / 對位、編輯球員、分享、存檔、設定 |
| 下方 | 復原、重做、分鏡切換（‹ 1/12 › ＋）、路線種類、手繪切換、刪除 |

> 範例圖中的「翻轉」與「角錐」不做。

### 10.2 視覺
照抄 `example.jpg`：橘色地板、白色線條、禁區為藍綠色漸層；藍隊和紅隊的圓標帶白框與陰影，名字顯示在圓標下方。

## 11. 資料模型（草案）

```ts
type Team = 'blue' | 'red';                     // blue = 使用者，red = 系統
type Mode = 'offense-design' | 'defense-design' | 'free';
type Position = 'PG' | 'SG' | 'SF' | 'PF' | 'C';
type Vec2 = { x: number; y: number };           // 公尺

interface Player {
  id: string;             // 'b1'..'b3', 'r1'..'r3'
  team: Team;
  number: number;
  name: string;
  position?: Position;
  heightCm?: number;
  weightKg?: number;
}

type PathKind = 'cut' | 'dribble' | 'pass' | 'screen';

interface TacticPath {
  id: string;
  kind: PathKind;
  actorId: string;        // 傳球時為傳球者
  targetId?: string;      // 傳球時為接球者
  points: Vec2[];         // 控制點（已簡化）
  freehand: boolean;
}

interface Frame {
  start: Record<string, Vec2>;   // playerId / 'ball' → 位置
  ballHolderId: string | null;
  paths: TacticPath[];           // 自由模式可以包含紅隊的路線
}

interface Tactic {
  version: 1;
  id: string;
  name: string;
  mode: Mode;
  screenDefense?: 'fight-over' | 'switch';     // 進攻設計模式使用
  matchups?: Record<string, string>;           // 進攻設計模式：藍隊 id → 紅隊 id（使用者指定）
  offensePlayId?: string;                      // 防守設計模式使用的內建戰術
  players: Player[];
  frames: Frame[];
  lastResult?: { grade: 'S' | 'A' | 'B' | 'C' | 'D'; expectedPoints: number };
  updatedAt: number;
}
```
