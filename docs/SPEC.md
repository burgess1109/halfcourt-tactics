# Halfcourt Tactics — 產品規格書 (v0.24)

> 3v3 半場籃球戰術 Web 小遊戲。使用者設計一方的戰術，系統模擬另一方，並評估結果。
> 技術：TypeScript + Vite + 原生 Canvas 2D，PWA。
> 本文件只描述目前實作的規格；里程碑、決策紀錄與待確認清單見 `docs/PLANNING.md`。

---

## 1. 產品定位

介於「戰術板」與「遊戲」之間。**使用者固定操作藍隊，系統固定操作紅隊**；由模式決定哪一隊進攻。

| 模式 | 狀態 | 藍隊（使用者） | 紅隊（系統） | 結果 |
|---|---|---|---|---|
| **進攻模式** | **已實作** | 進攻：選內建戰術或自己畫跑位、傳球、運球、掩護、投籃 | 防守 AI 依對位即時反應 | 評等、預期得分、戰術評價 |
| **防守模式** | **尚未實作**（首頁顯示「即將推出」，不能點；規劃見 `docs/PLANNING.md` M11） | — | — | — |

- 單一回合，不計比賽總分、不做連續多回合。
- 模擬**沒有隨機性**：只輸出期望值、評等與文字評價，不判定投籃是否命中。

### 1.1 進攻模式流程

```
首頁：選模式 → ① 藍隊球員資料 → ② 紅隊球員資料 → ③ 對位設定 → 戰術面板
```

| 步驟 | 內容 | 按鈕 |
|---|---|---|
| 首頁 | 「進攻模式」「防守模式（即將推出，不能點）」「開啟已存的戰術」（戰術列表，§8）、「問題回報」（和前一個按鈕同樣大小，新分頁開啟 GitHub Discussions） | — |
| ① 藍隊 | 三名球員：號碼、暱稱、身高、外線投射、速度、禁區終結、單打（§3.1） | 上一步 / **略過** / 下一步 |
| ② 紅隊 | 三名球員：號碼、暱稱、身高（§3.2） | 上一步 / **略過** / 下一步 |
| ③ 站位與對位 | 三個段落：**開局站位**（小球場自由放置、指定持球者、常用陣型）；**對位**（預設對位 + 使用者調整，§6.2）；**進階設定**（紅隊的防守方式：防守距離 一般 / 緊貼，預設一般；持球者切入時 不補防 / 弱邊補防，預設不補防；遇到掩護時 換防 / 擠過，預設換防，擠過時再選擋拆沉退 / 上提，預設沉退） | 上一步 / 開始 |
| 戰術面板 | 戰術庫與推薦（§6.3）、自行畫戰術、播放 | 上方「球隊設定」按鈕可回來修改 |

- **略過** = 這一步全部使用預設值，直接到下一步。之後仍可從戰術面板回來修改。
- **開局站位**：上方是「持球者」單選，下方是一個可以拖曳的小球場，兩者雙向同步。拖曳藍隊放到小球場範圍內的任何位置（拖到邊緣會停住，不會跑出畫面）；選單選或在小球場點一下球員，都能換人持球；紅隊依目前的對位即時站到防守位置（協防站位）。上方有常用陣型可以一鍵套用：弧頂＋兩翼（預設，1 號持球）、弧頂＋兩底角、兩翼＋低位、弧頂＋翼＋底角、弧頂＋兩肘；套用時持球者站到持球的位置，另外兩人依目前的左右順序就位。
  - 只影響空白戰術與自己畫的戰術；載入內建戰術時，站位由角色決定。
  - 目前的戰術還沒畫路線（只有一個分鏡、沒有路線）時，存檔後立刻套用；已經有路線時不動目前的戰術，提示「會在清空戰術或選空白戰術時生效」。
- **從戰術面板回來修改時**：不再是 1 → 2 → 3 的流程，改成「藍隊 / 紅隊 / 對位」三個分頁，可以直接切換；底部只有「完成」，**沒有「略過」**（避免把設定好的資料清回預設值）。切換分頁或按完成時會先驗證並儲存目前這頁。
- 步驟頁上方顯示進度（1 / 3、2 / 3、3 / 3）。

## 2. 球場

- **FIBA 半場**，世界座標單位為公尺，原點在底線中點，x 向右、y 朝中場。
- 可視範圍：寬 15 m（x ∈ [-7.5, 7.5]）× 深 14 m（y ∈ [0, 14]），外加約 0.8 m 的場外邊距。
- **籃框在畫面下方，不可翻轉。**

| 元素 | 尺寸 (m) |
|---|---|
| 籃框中心 | 距底線 1.575 |
| 籃板 | 距底線 1.2，寬 1.8 |
| 禁區 | 寬 4.9 × 深 5.8 |
| 罰球圈 | 半徑 1.8（禁區內那半邊用虛線） |
| 合理衝撞區 | 半徑 1.25（以籃框中心為圓心） |
| 三分線 | 半徑 6.75；底角直線距離邊線 0.9 |
| 中圈 | 半徑 1.8，只畫出靠本場的一半 |

## 3. 場上物件

### 3.1 藍隊球員（使用者，3 名）
| 欄位 | 必填 | 說明 | 預設 |
|---|---|---|---|
| 號碼 | ✅ | 0–99，同隊不可重複 | 1、2、3 |
| 暱稱 | ✅ | 1–12 字，顯示在圓標下方 | 球員 1、球員 2、球員 3 |
| 身高 (cm) | 選填 | 150–230 | 空白（模型使用 175） |
| 外線投射 | ✅ | 優勢 / 稍強 / 平均 / 稍弱 / 劣勢 | 平均 |
| 速度 | ✅ | 優勢 / 稍強 / 平均 / 稍弱 / 劣勢 | 平均 |
| 禁區終結 | ✅ | 優勢 / 稍強 / 平均 / 稍弱 / 劣勢 | 平均 |
| 單打 | ✅ | 優勢 / 稍強 / 平均 / 稍弱 / 劣勢 | 平均 |

- **能力是相對值，以場上六個人的平均為基準。** 「外線投射優勢」= 這位球員的投籃比場上的平均好很多。兩隊用同一個基準，換防後也不會說不通。
- 沒有「位置」與「體重」欄位：位置由四項能力表達，速度由「速度」能力決定，掩護與低位的效果看身高差。
- **資料完整**（才會出現戰術推薦，§6.3）= 藍隊步驟沒有略過，而且三人都填了身高。其他欄位都有預設值，所以不算在內。

### 3.2 紅隊球員（系統，3 名）
| 欄位 | 必填 | 說明 | 預設 |
|---|---|---|---|
| 號碼 | ✅ | 0–99，同隊不可重複 | 1、2、3 |
| 暱稱 | ✅ | 1–12 字 | 對手 1、對手 2、對手 3 |
| 身高 (cm) | 選填 | 150–230 | 藍隊同順序球員的身高（藍隊沒填則空白） |
| 速度 | ✅ | 優勢 / 稍強 / 平均 / 稍弱 / 劣勢（以場上六個人的平均為基準） | 平均 |

- 紅隊只有速度一項等級；外線、禁區、單打是進攻能力，紅隊在 v1 只負責防守，用不到。
- 藍隊能力和紅隊速度用同一組等級、同一個基準，可以直接相比：兩邊都是「平均」時一樣快。

### 3.3 編輯與顯示
- 戰術面板上點擊球員，會開啟該隊的設定頁並跳到該球員。
- 身高留空時，即時顯示模型使用的值，以及換算後的跑動與運球速度。

### 3.4 球
- 獨立物件，可以單獨拖曳。
- 拖曳到球員附近（0.6 m 內）時會吸附，成為該球員的持球狀態。
- 任何時刻只有一顆球，也只有一位持球者（或球在空中）。

### 3.5 掩護標記
- 以「路線種類」的形式存在（見 §4）：跑位線的終點畫成 T 字，代表球員在該點設立掩護。

## 4. 路線

| 種類 | 樣式 | 意義 |
|---|---|---|
| 跑位 | 實線 + 箭頭 | 無球移動 |
| 運球 | 波浪線 + 箭頭 | 持球者移動，球跟著移動 |
| 傳球 | 虛線 + 箭頭 | 球從 A 飛到 B，起點必須是持球者，終點必須是隊友 |
| 掩護 | 實線 + T 字端點 | 移動到終點後設立掩護 |
| 投籃 | 點狀弧線 + 籃框外的目標圈 | 持球者出手，**回合結束**。只能在最後一個分鏡；點持球者即建立，不用拖線，弧線自動產生、不能編輯 |

- **繪製方式**：
  - **預設（平滑）**：拖出起點到終點，途中可以點選控制點，系統自動用 Catmull-Rom 平滑成曲線。
  - **手繪**：切換成手繪模式後，記錄手指軌跡，用 RDP 演算法簡化點數（容差 0.1 m）後再做平滑。
- 進攻模式下只能畫**藍隊**的路線；紅隊的移動由防守 AI 產生，不能畫、不能拖曳。
- 每位球員在每個分鏡最多一條路線；畫新的路線會取代舊的。
- 路線的起點永遠跟著球員：分鏡開始時的位置被拖走，路線起點也跟著移動。
- **傳球**：傳球者在同一個分鏡不能同時移動（因為一人只有一條路線）；傳球終點指向接球者在本分鏡**結束時**的位置，接球者改變跑位時會自動跟著改。
- 球換人持有時，舊持球者的運球、傳球與投籃路線會自動移除，並提示使用者。
- 已經投籃時，不能在最後一個分鏡後面新增分鏡（可以在前面插入）。
- 移動路線的終點會顯示該球員的半透明分身。

### 4.1 編輯操作
| 操作 | 方式 |
|---|---|
| 選工具 | 下方工具按鈕開啟選單：移動 / 跑位 / 運球 / 傳球 / 掩護 / 投籃，以及「手繪」開關 |
| 畫線 | 選好路線種類後，從球員（或球）拖出去；太短（< 0.6 m）視為誤觸 |
| 選取路線 | 點路線本身 |
| 加彎 | 選取後，拖曳兩個控制點中間的「＋」把手，會插入新的控制點 |
| 移動控制點 | 拖曳白色圓點（起點固定在球員身上；傳球終點固定在接球者身上） |
| 刪除控制點 | 點一下中間的白色圓點 |
| 刪除路線 | 選取後按刪除鍵或垃圾桶 |
| 鍵盤（桌機） | V 移動、1 跑位、2 運球、3 傳球、4 掩護、5 投籃、F 手繪、Del 刪除、Esc 取消、⌘/Ctrl+Z 復原、⇧⌘Z / Ctrl+Y 重做 |

## 5. 分鏡與播放

- 一個戰術由 **N 個分鏡** 組成，**1 ≤ N ≤ 12**。
- 每個分鏡保存：「分鏡開始時所有物件的位置」加上「本分鏡的所有路線」。
  下一個分鏡的起始位置 = 上一分鏡路線的終點（自動帶入）。
- **播放**：按下播放後，從第一個分鏡完整播到最後一個分鏡，v1 不做暫停、調速、逐步播放。
  - 球員依路線移動，速度由 §7 的速度模型決定，所以不同球員會有先後抵達的差異。
  - 傳球：球沿著傳球線飛行，速度 12 m/s。**不做抄截。**
  - 分鏡內所有移動都結束後，才進入下一個分鏡。
- **站位鎖定**：只有第 1 個分鏡可以拖曳藍隊球員與球（紅隊站位由防守 AI 依對位決定）；之後分鏡的站位與持球者都由上一個分鏡推算（傳球後由接球者持球），只能畫路線。改動前面的分鏡時，後面分鏡會自動更新，不再成立的路線會被移除並提示。
- **掩護者先站住**：上一個分鏡設了掩護的人，這個分鏡先在原地站 0.5 秒才開始移動（等持球者利用掩護後才下順或外彈）。
- **分鏡內的時間**：所有球員同時出發；傳球的出手時間讓球剛好在接球者跑到終點時抵達（接球者不動則立刻出手）。沒有任何移動的分鏡停留 0.5 秒。
- **分鏡操作**：「‹ ›」切換、「＋」在目前分鏡後面新增、點「n / N」開選單刪除目前分鏡。新增、刪除都算一步，可以復原。
- 球場上方顯示目前分鏡時長與總時間；超過 12 秒時變紅。
- **投籃**：分鏡一開始就出手，球沿弧線飛進籃框（水平速度 8 m/s，至少 0.5 秒）。
- **時長**：每個分鏡約 1–3 秒。**出手時間**（沒有投籃時為總時間）超過 **12 秒**（3x3 的進攻時限）時**顯示警告**，但仍然可以播放和存檔。評價中也會列出這一點（見 §6.5）。

## 6. 模擬引擎

### 6.1 原則
- 固定時間步長（1/60 s），**完全決定性**：同樣的輸入一定得到同樣的結果，所以分享連結可以重現同一個結果。
- 模擬邏輯要與繪圖分離（純 TS 模組，可以寫單元測試）。
- 所有係數集中在 `sim/config.ts`。

### 6.2 對位與防守 AI（紅隊防守）

**預設對位（步驟 ③）：**
- 藍隊三人**都有填身高** → 依身高排序配對：藍隊最高的對紅隊最高的，依此類推（紅隊用實際值或預設值；同高時維持原本順序）。
- 否則 → 依步驟 ①② 的順序配對（藍 1 對紅 1、藍 2 對紅 2、藍 3 對紅 3）。
- 使用者可以重新配置：點藍隊球員，再點要對位的紅隊球員，兩人交換對象。畫面同時顯示每組的身高差與速度差。

**防守 AI（人盯人）：**
- 每 1/60 秒更新一次。藍隊只照路線移動、不受紅隊影響，所以先算出藍隊的位置，再推進紅隊；完全決定性。
- **防守位置**：
  - **防外圍、離持球者 3.5 m 以內的無球者**（例如正在掩護）：
    - 站著時：貼在他身邊，距離和防持球者相同（一般 1.5 m、緊貼 1.45 m），方向 = 往籃框 + 往持球者 × 0.7（以籃框那一側為主、偏向持球者），隨時準備換防、上提或協防，不退到他身後的禁區裡。這個位置離防持球者的人（持球者和籃框之間 1.5 m）不到 1.45 m 時，沿著「離對位者同樣距離的圓」轉到最近的不重疊角度（兩邊都行時選離持球者比較近的一邊），兩個紅圈不會疊在一起。
    - 往籃框切時（往內速度 ≥ 1.5 m/s，例如掩護後順下）：回到他和籃框之間（同下一條），擋住順下。
  - 防持球者、防籃下附近（離籃框 4.5 m 以內）的無球者：在「對位球員與籃框的連線上」，防持球者 1.5 m、防無球者 2.0 m；對位者靠近籃框時退到兩人中間，但至少 1.45 m。圓標直徑約 1.44 m，距離比真實比賽略大，圓標才不會疊在一起。
  - **協防站位**（平常，包含開局站著不動）：防外圍（離籃框超過 4.5 m）的無球者時，站在對位者與籃框之間（2.0 m），再往持球者方向偏 0.8 m，守住內切。
  - **阻絕**（有記憶）：對位者往外跑（離籃框的速度 ≥ 1.5 m/s）想出來接球時，站到傳球路線上：對位者 + 往持球者方向 1.3 m + 往籃框方向 0.5 m；對位者停在外圍等球也繼續阻絕，直到他往籃框切（往內速度 ≥ 1.5 m/s）才回到協防站位。所以「先往外拉、再背切」能甩開防守者；換防後重新判斷。
  - 球在空中（傳球飛行中）時不阻絕，退回人和籃框之間。
- **往球的方向靠**（jump to the ball）：看到對位者把球傳出去後，防守者有 0.8 秒往接球者的方向移動（最多 2 m、最多到兩人中間）。對位者這時往籃下切（傳切），就會從防守者背後過去；沒有切的話，防守者就回到原本的站位。
- **被甩開只能從後面追**：對位者擋在防守者和籃框之間（對位者比防守者更靠近籃框超過 0.3 m，而且從對位者看，防守者和籃框的夾角大於 120°）時，防守者穿不過去，改追在對位者身後；對位者往外走、或防守者回到側邊後恢復正常。只是往籃下走（例如要位）、防守者還在旁邊時，不算被甩開。
- **反應時間 0.2 秒**：防守者看到的是 0.2 秒前的場上狀況（包含傳球後誰持球）。
- **移動速度**：§7 的速度 × 0.9（側滑、倒退比衝刺慢）。所以防運球者只能慢慢追回、防空切會被甩開，追不上就是追不上。
- **身體碰撞**：防守者不能穿過進攻者，兩人中心至少相距 1.3 m。
- 第 2 個分鏡之後，編輯畫面上的紅隊位置 = 模擬中該分鏡開始時的實際位置（可能被甩開或還在換防）。
- 播放時，被掩護卡住的防守者外圍會亮黃色光暈。
- **掩護判定**：掩護者到位之後、離開掩護點 0.5 m 之前，若防守者中心離掩護者 1.4 m 以內，而且掩護者擋在他要去的方向上，就算被掩護到。每個掩護只觸發一次。
- **防守距離**（步驟 ③ 選擇，**預設一般**，全隊適用；小球場上的紅隊站位跟著改變）：
  - **一般**：上面的距離與協防站位 / 阻絕規則。
  - **緊貼**：防持球者 1.45 m（圓標不重疊的極限）、防無球者 1.5 m；外圍無球者不管有沒有往外跑，一律站在傳球路線上阻絕（開局也是）。好處是出手時干擾比較大、外圍不好接球；代價是持球者切入、無球者背切或空切時，防守者比較容易被甩到身後、從後面追。18 套內建戰術的預期得分總和兩者相近（例如擋拆外拉對緊貼比較難，假手遞手接背切則會被打穿）。
  - 擋拆上提、換防後的距離也依這個設定。
- **掩護應對**（步驟 ③ 選擇，**預設換防**）：
  - 換防：被掩護的防守者停住 0.3 秒，然後和掩護者的防守者交換對位；換防後可能形成身高錯位。
  - 擠過：被掩護的防守者停住 t 秒後繼續追原本的人；t = 0.45 + 0.015 ×（掩護者身高 − 防守者身高），介於 0.25–0.9 秒。
    - **擋拆的協防**（擠過底下的進階選項，**預設沉退**；換防時隱藏、不適用）：被掩護的人盯的是持球者時（持球掩護），盯掩護者的防守者暫時離開掩護者去協防持球者。無球掩護沒有協防。
      - **沉退 Drop**：退到持球者和籃框的連線上、離籃框 3.0 m（罰球線下方；持球者很靠近籃框時，最多到離他 1.5 m），保護籃下。切入、拋投、掩護者順下比較難；中距離以外急停跳投、掩護者拉開到外線比較空。
      - **上提 Hedge**：站到持球者和籃框之間、離他 1.5 m（和防持球者相同），干擾投籃與切入。持球者不好直接出手；掩護者順下或拉開比較空。
      - 協防至少 1 秒（掩護常在持球者開始運球前就設好）。之後被掩護的隊友追回理想位置 1.0 m 內、而且離籃框比持球者近 0.8 m 以上（真的擋在前面），或持球者把球傳出去（防守者有 0.2 秒反應時間，只算協防開始之後看到的傳球；接球後馬上擋拆時，接球前的持球者不算），或協防滿 2.5 秒，就回去盯掩護者。
      - **沉退時掩護者順下**：協防開始之後，看到掩護者往籃框移動（速度 ≥ 2 m/s），而且離籃框不到「這一刻的沉退位置 ＋ 1.5 m」（快要超過協防的人；持球者在外面時是 3.0 ＋ 1.5 = 4.5 m，持球者靠近籃框、沉退位置變深時門檻跟著變小）時，協防的人立刻回去盯他（不受「至少 1 秒」限制）。用沉退位置比較、而且要真的在移動：協防的人平常就站在掩護者和籃框之間，只比距離的話一開始就會成立；掩護者跑去設掩護的那段移動也不算。不讓順下的人跑到身後；持球者交給被掩護的隊友去追，急停跳投就比較空。
      - 判斷協防、補防的開始與結束時，紅隊和藍隊都用「看到的那一刻」（0.2 秒前）的位置比較，兩邊時間一致。
      - 藍隊的跑位照路線走，協防不會讓持球者減速；效果反映在出手時的空檔程度與評價。
      - 協防只處理擋拆當下：被掩護的隊友回到位置後，持球者如果再甩開他切入，要看下面的「持球者切入時」設定。
- **持球者切入時**（步驟 ③ 選擇，**預設不補防**，目前的評分都以不補防校正）：
  - **不補防**：持球者甩開防守者也不會有人補，其他人守住自己的人。
  - **弱邊補防**：持球者往籃框切、甩開自己的防守者時，另外兩位無球防守者中**來得及的人**補到切入路線上。用「比誰先到」判斷，不用固定距離：
    - **觸發**：持球者離籃框 6 m 以內、往籃框的速度 ≥ 2 m/s，而且他的防守者已經沒有正常擋在前面（離籃框只比持球者近不到 1.0 m；正常約 1.5 m）。等到真的被超過才補就太晚了。
    - **來不來得及**：在持球者到籃框的直線上、離籃框 4.0、3.5 … 1.5 m 的點，補防者（反應時間 0.2 秒＋距離÷速度）要比持球者（距離÷速度）早到 0.1 秒以上；選離籃框最遠（迎得最前面）的點。兩人都來得及時，選能迎得比較前面的人；都來不及就不補。所以被拉到底角、外圍的弱邊防守者通常補不到，球員速度也會影響。
    - **補防時**：站在那個點（持球者已經更靠近籃框時，站在他前面 1.5 m），他原本盯的人沒人管。
    - **結束**：持球者把球傳出去（只算補防開始之後看到的傳球）、持球者的防守者追回前面（離理想位置 1.0 m 內，而且離籃框比持球者近 1.3 m 以上）、或滿 2 秒，就回去盯自己的人；結束後 0.5 秒內不會再補。
    - 一次只有一個人補防；被掩護卡住、正在擋拆協防的人不補；反過來，正在補防的人也不會被派去擋拆協防。不做輪轉（3 對 3 沒有第三個人接手補防者的人），也不補空手切入。
    - 代價：補防者原本盯的人會空出來，評價的「其實傳給 X 更空」會指出來。緊貼時外圍一律阻絕，防守者站得比較外面，補防放空的人更明顯。
- 系統**不做**區域聯防、輪轉補位與空手切入的補防。

**推薦演算法（藍隊資料完整時才出現，§3.1）：**
1. 分數（0–4，平均 = 2）：
   - 外線投射、禁區終結、單打：直接用能力等級（優勢 = 4、稍強 = 3、平均 = 2、稍弱 = 1、劣勢 = 0）。
   - 身高、速度：跟步驟 ③ **對位的防守者**比。身高每差 5 cm 算一級、速度每差 5% 算一級（速度包含身高與雙方的速度等級），超過 0–4 就截斷。
2. 每套戰術的每個角色對各項有權重（`src/plays/library.ts` 的 `weights`，`docs/PLAYS.md` 的「推薦時看重」）。
3. 戰術分數 = Σ 權重 × 分數 ÷ Σ 權重，權重項目多的戰術不會因此佔便宜。三名球員分配到三個角色共 6 種排法，取分數最高的排法（同分取排列順序在前的）。
4. **角色分配**看適合度；**排序**則用這個分配實際跑一次防守模擬並評分（§6.4），依**預期得分**由高到低（同分時看適合度，再維持戰術庫順序），列出**前 5 名**，並附一句理由（取貢獻最大的一項，例如「2 號外線投射優勢，適合外彈投籃」）。推薦卡片上的「預期評等」和點下去播完的評分一致。
5. 完全決定性：同樣的資料一定得到同樣的推薦。

**操作：**
- 戰術面板的「戰術庫」面板：上方是推薦（資料完整時），下方是全部 18 套（資料不完整時只顯示這部分，仍可點選播放）。
- 上方工具列第二個按鈕（書本圖示）開啟戰術庫。打開時先顯示「正在模擬戰術 n / 18…」，逐套模擬完才顯示結果（關閉面板就停止）；球員、對位、掩護應對沒變時直接用上次的結果。每套戰術都標示預期評等與預期得分。面板由上到下：
  1. **空白戰術**：清掉目前的跑位，回到預設站位自己畫；球員資料、對位與掩護應對保留。算一步，可以復原。
  2. **球隊總評**（資料完整時）：每人一行，列出強項（能力「稍強」以上、比對位者高 5 cm 以上、快 5% 以上）→ 適合的戰術類型（外線出手、切入或下順、持球單打、空切或切入、低位或下順）與最多 3 套例子；最後一句整體建議（主要攻擊點、第二選擇、最適合的戰術）。同強度時，以對應戰術在推薦中的名次排序，讓總評和推薦清單一致。
  3. **推薦給你的球隊**（資料完整時）前 5 名；資料不完整時改為提示「藍隊三人都填了身高，就會推薦」，並有按鈕直接前往設定。
  4. 全部戰術，依類別分組。
- 點擊戰術 → 依推薦的角色分配（從全部清單點選時，也自動找最佳分配）載入成分鏡，並**立刻自動播放一次**；紅隊依防守 AI 移動。載入算一步，可以按復原回到原本的戰術。
- 球場上方顯示目前的戰術名稱；修改過分鏡（路線、站位、分鏡數）後顯示「根據〈戰術名〉修改」。只改球員資料或對位不算修改。
- 載入後可以繼續修改藍隊的路線、增減分鏡，但**內建戰術本身永遠不會被改寫**：修改的是一份複本，畫面標示「根據〈戰術名〉修改」，要保留就存檔成自己的戰術（§8）。再點一次同一套內建戰術，會重新載入原始版本。

### 6.4 評估與評等
- **評哪一球**：
  - 使用者有畫投籃，就評**這一球**，並在評價中列出「更好的出手選擇」（如果有）。沒有畫投籃也可以播放（不強制），但不評分（見下方）。
- **沒有投籃就不評分**：不給評等與預期得分，卡片顯示「未評分：沒有投籃」，並提示最後一刻誰最有機會（不附分數）；掩護、空間等評價照常列出。
- **評估時間點**：出手那一刻。位置與防守都取自模擬（§6.2）。
- **區域**：弧外（`isBeyondArc`，含底角直線段）2 分、看外線；禁區（|x| ≤ 2.45、y ≤ 5.8）1 分、看禁區終結；其他弧內位置是中距離 1 分、看外線。
- **只有在出手者與籃框之間（前方或並排）的防守者算干擾**：防守者離籃框的距離不比出手者遠超過 0.3 m。比出手者離籃框更遠的防守者已被甩開、追在後面，不管多近都不算干擾；所有防守者都被甩開時就是完全空檔。評語只有在所有防守者都在身後時才寫「對方都追在身後」；前方有人但在 3.0 m 外時寫「完全空檔（最近的防守者 x m）」，距離與標記都用前方最近的那位，不用身後緊追的人。（用距離比較而不是方向，靠近籃框時才不會誤判。）
- **空檔程度**：干擾距離 = 防守者的實際距離；出手前那個分鏡（或出手的分鏡）有運球時，依單打 +0 / 0.15 / 0.3 / 0.45 / 0.6 m。
  干擾距離 ≥ 3.0 m 為完全空檔；≤ 1.3 m（貼身）時干擾讓命中率損失 50%，中間線性。
- **身高錯位**（例如換防後）：出手者每比干擾他的防守者高 1 cm，干擾造成的損失少 4%（禁區出手），最多少 80%；跳投（中距離、弧外）效果減半。防守者比較高時，損失最多增加 50%。例：換防後在禁區高 20 cm，被貼身時命中率從 50% 損失變成只損失 10%。
- 取造成損失最大的那位防守者計算。速度錯位不另外計算：較慢的防守者在模擬中追不上、被甩開，空檔自然變大。
- **出手超過 12 秒**：違例，預期得分記 0、評等 D。
- **出手價值**：依區域（禁區 / 中距離 / 弧外）× 出手者的能力等級（§7.2）得出命中率，再乘上該區分數，得出預期得分（xPts）。
- **計分規則**：採 **FIBA 3x3**，弧內 1 分、弧外 2 分。
- **評等**（門檻集中在 `sim/config.ts`）：

| 評等 | 預期得分（xPts） |
|---|---|
| S | ≥ 0.75 |
| A | ≥ 0.60 |
| B | ≥ 0.48 |
| C | ≥ 0.36 |
| D | < 0.36 |

> 門檻依 18 套戰術的實測結果校正。參考：外線優勢的人空檔投弧外 ≈ 0.90（S）、禁區終結優勢的人甩開防守者上籃 ≈ 0.83（S）、平均能力的人空檔投弧外 ≈ 0.64（A）、平均能力的人甩開防守者上籃 ≈ 0.55–0.60（A / B）、被貼身干擾 < 0.36（D）。18 套戰術在全員平均時分布為 A 10、C 6、D 2：甩開防守者的出手是完全空檔（A），被防守者擋在前方的是 C / D。

### 6.5 戰術評價（文字）
**完整播完**（不是中途按停止）後顯示評分卡片：評等、預期得分、3～5 條評價。每條都指向具體的分鏡和球員，點擊後跳到該分鏡，並在場上用白色光圈標示（3 秒後或點場上任一處消失）。卡片不蓋住球場：直式放在球場下方、橫式放在右側，球場依剩下的空間縮放。戰術一有修改，卡片就關閉，上次的評分（`lastResult`）也一併清除。
- 評價最多 5 條，依重要性挑選：出手 → 違例 → 命中率 → 更好的選擇 → 掩護與補防 → 空間 → 出手時間；挑完後仍依原本的順序顯示。補防不到 0.3 秒（例如剛補就傳球：補防者要過 0.2 秒反應時間才看到傳球，門檻要明顯高於它）不寫評語；有寫時例如「第 2 分鏡，對手 3 從弱邊補防 球員 1 的切入 0.8 秒，原本盯的 球員 3 沒人管」。
- 只列出**出手之前**發生的掩護；換防的錯位說明用「那次換防之後」的對位。擋拆擠過時另外說明協防方式與時間，例如「對手 2 沉退保護籃下 1.3 秒：球員 1 往籃下切會被擋，中距離以外急停跳投、或球員 2 拉開到外線比較有空間」。
- 空間配置不算正在掩護的人（最近一條路線是掩護，之後留在原地繼續擋人也算）；出手者照算（隊友擠在出手者旁邊也該提醒）。

評價由規則產生：

| 類型 | 範例 |
|---|---|
| 最佳出手 | 「第 4 分鏡，球員 3 在右底角空檔 2.4 m，預期得分 1.18」 |
| 掩護成效 | 「第 2 分鏡的掩護讓防守者延遲 0.6 秒」／「掩護太早，防守者已經繞過」 |
| 空間配置 | 「第 3 分鏡，球員 2 和球員 4 距離不到 3 m，擠壓了切入空間」 |
| 對位優勢 | 「換防後形成 球員 5（C）對 球員 1（PG）的錯位，低位有 +18 cm 的身高優勢」 |
| 時間 | 「第 13.2 秒才出手，超過 12 秒進攻時限，違例不計分」／「第 3.8 秒出手，在 12 秒進攻時限內」 |
| 命中率 | 「2 號 阿華 的禁區終結「平均」，禁區空檔命中率 68%，受干擾後剩 61%（比干擾他的防守者高 20 cm，干擾減少 80%）」（說明分數從哪裡來） |
| 終結點 | 「球員 2 的出手被干擾，其實球員 3 在弧頂更空」；沒有投籃時不評分，只提示最後一刻誰最有機會 |

## 7. 球員能力模型

> 以下係數集中在 `sim/config.ts`。
> 等級：優勢 / 稍強 / 平均 / 稍弱 / 劣勢（分數 4 → 0），以場上六個人的平均為基準；藍隊四項能力與紅隊速度共用。

### 7.1 速度
```
base = 5.0 m/s（無球跑動）
運球 ×0.85
身高 = clamp(1 - 0.003·(身高-175), 0.92, 1.08)      兩隊都適用，紅隊的身高因此仍有作用；175 cm = 1.00
速度等級 = 4: 1.10 / 3: 1.05 / 2: 1.00 / 1: 0.95 / 0: 0.90     藍隊看能力的「速度」，紅隊看自己的「速度」
speed = base × 身高 × 能力
```

### 7.2 能力等級的作用
| 能力 | 作用 | 優勢 / 稍強 / 平均 / 稍弱 / 劣勢 |
|---|---|---|
| 外線投射 | 弧外（2 分）與中距離（1 分）的空檔命中率 | 弧外 45 / 39 / 32 / 22 / 10 %；中距離 65 / 58 / 50 / 43 / 35 % |
| 速度 | 跑動與運球速度（§7.1） | ×1.10 / 1.05 / 1.00 / 0.95 / 0.90 |
| 禁區終結 | 禁區（含拋投，1 分）的空檔命中率 | 85 / 77 / 68 / 60 / 50 % |
| 單打 | 運球切入或急停時，與對位者拉開的距離 | +0.60 / 0.45 / 0.30 / 0.15 / 0 m |

- 兩端（優勢、劣勢）由使用者指定；中間三級依一般業餘球員空檔出手的水準估計。弧外多數人集中在 30% 上下，所以劣勢到稍弱落差較大。
- 有人防守時，命中率依空檔程度往下修正（§6.4）。

### 7.3 對位優勢
- **身高差** → 出手時受到的干擾、傳球的干擾範圍、掩護的效果、低位單打的效果。
- **速度差** → 切入時能不能甩開對位者。
- 對位設定頁顯示每組的差異（例如「身高 +8cm / 速度 −5%」）。

### 7.4 未填時的預設值
- 藍隊：身高 175 cm。
- 紅隊：藍隊同順序球員的身高；藍隊也沒填則 175 cm。

## 8. 存檔與分享

- **戰術必須命名**（1–30 字，前後空白不算）。第一次存檔、或戰術還沒有名稱時，跳出輸入名稱的對話框；從內建戰術載入、還沒修改過時，預設填入戰術名稱（例如「高位擋拆-Pull-up Jumper」）。已經有名稱時，按存檔（或 ⌘S / Ctrl+S）直接覆蓋同一份。
  - 改名稱不算修改戰術內容：不算一步、不清掉評分；復原紀錄裡同一份戰術的名稱也一起改，按復原不會變回舊名稱。
  - 球場上方顯示戰術名稱；存檔後又修改過，顯示「名稱・未存檔」。還沒命名時，沿用「內建戰術名稱 / 根據〈…〉修改」。
- **戰術列表**（localStorage，上方工具列與首頁都能開啟）：依最後修改時間排列，顯示名稱、評等與預期得分、修改時間、根據哪一套內建戰術；目前開啟的那份會標示出來。
  - **開啟**：換成已存的版本，原樣載入（評分、修改時間、內建戰術來源都不變，所以不會顯示未存檔）；算一步，可以復原回剛才的戰術（內容和目前完全相同時不算一步）。重新開啟正在編輯的同一份，等於放棄還沒存的修改。
  - **重新命名**（在列表上直接改）、**複製**（新的一份，名稱加「複本」）、**匯出 JSON**、**刪除**（按兩次確認）。
  - 播放後的評分：戰術存檔後沒有再修改時，評分自動更新到已存的版本，列表才看得到最新評等。
  - 其他分頁改了列表時自動更新。localStorage 被停用時改存在記憶體，並提示關閉頁面後就會消失。讀取時損壞的項目會略過並提示。
- **JSON**：戰術列表可以匯入、匯出單一戰術檔；分享對話框也可以下載目前戰術的 JSON 檔。匯入時檢查版本並驗證全部內容（球員、對位、分鏡數量、座標範圍、每人每分鏡一條路線、投籃只在最後一個分鏡…），不正確時顯示原因；持球者不對的運球、傳球會被移除並提示數量。匯入的戰術 id 和已存的重複時當成新的一份，沒有名稱時用檔名。紅隊位置與後面分鏡的站位一律重新推算，不採用檔案裡的值。
- **分享連結**：`https://…/#p=<base64url(deflate-raw(JSON))>`（瀏覽器內建的 CompressionStream，不需要套件）
  - 只帶使用者畫的部分與設定：第 1 個分鏡的藍隊與球、每個分鏡的路線、球員、對位、掩護應對、開局站位、內建戰術來源。座標四捨五入到公分；手繪路線在畫完時已經簡化；投籃弧線、路線 id、紅隊位置、後面分鏡的站位都在開啟時重新推算；不帶評分（開啟後自己播放）。測試確保 18 套內建戰術的連結都在 2000 字以內（例如高位擋拆約 730 字）。
  - 分享對話框：顯示連結、「複製連結」（沒有剪貼簿權限時選取文字讓使用者自己複製）、「傳送到其他 App」（支援 Web Share 的裝置）、「下載 JSON 檔」。
  - 開啟分享連結時直接進入**唯讀預覽**：球場上方顯示「分享的戰術・唯讀」與名稱，可以切換分鏡、播放、看評分，但不能拖曳、畫線、復原、清空、增刪分鏡、改球隊設定或開戰術庫。按「**另存**」輸入名稱後才寫入戰術列表並開始編輯（新的 id，不會覆蓋任何已存的戰術）；按「**關閉**」回到開啟連結前的畫面與戰術。從戰術列表開啟其他戰術也會結束預覽。
  - 連結損壞時提示「分享連結不完整或已損壞」並留在首頁。播放中開啟分享連結時，先停止播放再進入預覽。
- 資料帶 `version` 欄位（目前 1），比目前版本新的資料提示重新整理頁面；之後格式改變時在讀取時遷移。

## 9. 編輯操作

- 復原 / 重做：**最多 5 步**。每一步是一次完整操作：拖曳放開、完成一條線、送出編輯。
- 刪除：先選取物件，再按刪除（球員不能刪除，只能刪除路線）。
- **清空戰術**（重做旁邊的橡皮擦按鈕）：回到開局站位、清掉所有路線與分鏡，球員資料、對位、掩護應對保留；和戰術庫的「空白戰術」相同。算一步，可以復原；已經是空白戰術時停用。
- 編輯中切換分鏡時，歷史紀錄不清空。

## 10. 版面與平台

- **直式**：上方工具列 / 球場 / 下方工具列。
- **橫式**：球場置中，工具列移到左右兩側；籃框仍然在球場的下方。
- 不支援縮放和平移。
- 高解析度螢幕：canvas 依 `devicePixelRatio` 縮放。
- 觸控與滑鼠統一使用 Pointer Events，canvas 設定 `touch-action: none`。
- **PWA**：使用 `vite-plugin-pwa`（只在打包時使用），預先快取所有檔案，可以離線使用、加到主畫面（含 iOS 的 apple-touch-icon）。有新版本時在背景更新，重新整理後生效。
- 介面語言：繁體中文。
- **按鈕提示**：滑鼠移到工具列、分鏡列的按鈕上約 0.3 秒，顯示按鈕用途與快捷鍵（停用的按鈕顯示「即將推出」）；橫式時，左右兩側工具列的提示分別出現在按鈕右邊、左邊。觸控裝置沒有 hover，不顯示。

### 10.1 工具列
| 位置 | 按鈕 |
|---|---|
| 上方 | **戰術列表**、**戰術庫**、播放、**球隊設定**（藍隊 / 紅隊 / 對位）、**分享**、**存檔**、設定（即將推出） |
| 下方 | 復原、重做、**清空戰術**、分鏡切換（‹ 1/12 › ＋）、路線種類、手繪切換、刪除 |

球場左下角另有「問題回報」連結（評分卡片在下方時跟著往上讓位），新分頁開啟 <https://github.com/burgess1109/halfcourt-tactics/discussions>。

### 10.2 視覺
原木色地板、白色線條、禁區為深藍色漸層；藍隊和紅隊的圓標帶白框與陰影。顏色集中在 `src/render/theme.ts`。
- 路線底下有一層半透明的白色外框（每邊約 1.5 px，虛線照同樣的間隔），路線在原木地板與深藍禁區上都看得清楚；選取時的白色外光比外框更寬。戰術說明的分鏡圖也一樣。
- 圖示：工具列與選單使用 Phosphor Icons 的 Bold 樣式（MIT，授權聲明見 `public/THIRD_PARTY_NOTICES.txt`）；跑位以外的路線圖示（運球、傳球、掩護、投籃）是自己畫的線條圖示，線條粗細配合 Bold 樣式。全部放在 `index.html` 的 SVG sprite。
- 名字：**藍隊顯示在圓標上方、紅隊顯示在下方**。防守者通常站在對位者靠籃框那一側（畫面下方），這樣名字不會被蓋住。
- 持球時，球畫在持球者右側。

## 11. 資料模型

```ts
type Team = 'blue' | 'red';                     // blue = 使用者，red = 系統
type Mode = 'offense' | 'defense';
type Rating = 0 | 1 | 2 | 3 | 4;   // 劣勢 / 稍弱 / 平均 / 稍強 / 優勢（以場上六個人的平均為基準）
type Vec2 = { x: number; y: number };           // 公尺

interface Skills {
  shooting: Rating;   // 外線投射
  speed: Rating;      // 速度
  finishing: Rating;  // 禁區終結
  iso: Rating;        // 單打
}

interface Player {
  id: string;             // 'b1'..'b3', 'r1'..'r3'
  team: Team;
  number: number;
  name: string;           // 暱稱
  heightCm?: number;
  skills?: Skills;        // 只有藍隊
  speedRating?: Rating;   // 只有紅隊，未填 = 平均
}

type PathKind = 'cut' | 'dribble' | 'pass' | 'screen' | 'shot';

interface TacticPath {
  id: string;
  kind: PathKind;
  actorId: string;        // 傳球時為傳球者
  targetId?: string;      // 傳球時為接球者
  points: Vec2[];         // 控制點（已簡化）
  freehand: boolean;
}

interface Frame {
  start: Record<string, Vec2>;   // playerId / 'ball' → 位置（紅隊由防守 AI 推算）
  ballHolderId: string | null;
  paths: TacticPath[];           // 只有藍隊的路線
}

interface Tactic {
  version: 1;
  id: string;
  name: string;
  mode: Mode;
  setup: {
    blueSkipped: boolean;
    redSkipped: boolean;
    matchupsCustomized: boolean;
    lineup?: { positions: Record<string, Vec2>; holder: string };   // 開局站位：三名藍隊的位置與持球者
  };
  matchups: Record<string, string>;            // 藍隊 id → 紅隊 id
  screenDefense: 'fight-over' | 'switch';
  pickCoverage: 'drop' | 'hedge';              // 擠過時擋拆的協防：沉退 / 上提（舊資料沒有這個欄位時當作沉退）
  pressure: 'normal' | 'tight';                // 防守距離：一般 / 緊貼（舊資料沒有這個欄位時當作一般）
  driveHelp: 'off' | 'weak-side';              // 持球者切入時：不補防 / 弱邊補防（舊資料沒有這個欄位時當作不補防）
  basedOn?: { playId: string; roles: Record<'A' | 'B' | 'C', string>; modified: boolean };  // 從戰術庫載入時
  players: Player[];
  frames: Frame[];
  lastResult?: { grade: 'S' | 'A' | 'B' | 'C' | 'D'; expectedPoints: number };
  updatedAt: number;
}
```
