### M8 之後追加的功能

都在站位與對位頁的「進階設定」（SPEC §1.1、§6.2）：

- 擠過時的擋拆協防：沉退 / 上提（預設沉退）
- 紅隊的防守距離：一般 / 緊貼（預設一般）
- 持球者切入時：不補防 / 弱邊補防（預設不補防）

### M9：GitHub CI/CD

- **CI**：push 與 pull request 時執行型別檢查、單元測試、打包（`npm run typecheck`、`npm test`、`npm run build`），任何一步失敗就標示失敗。
- **CD**：推到 `main` 且 CI 通過後，把 `dist/` 部署到 GitHub Pages（Settings → Pages 的 Source 選 GitHub Actions）。
- workflow：`.github/workflows/ci.yml`，`build`（型別檢查、測試、打包）＋ `deploy`（只在 main）。Node.js 24。pull request 有新的 push 會取消舊的檢查；main 不取消，避免部署做到一半被中斷。
- 前置作業（使用者操作）：建立 GitHub repo（免費方案需為 public）、設定 remote 並推送、打開 Pages。
- **可驗收**：推一個 commit 到 `main`，幾分鐘內 `https://<帳號>.github.io/<repo>/` 更新；可以離線使用、加到主畫面；分享連結在部署的網址上能正確還原。測試失敗的 commit 不會被部署。

### M10：英文語系

- 介面文字集中管理：目前文字直接寫在各個 UI 檔案裡，要先抽出成「繁體中文 / 英文」兩份文字表。
- 範圍：首頁、設定流程、戰術面板、工具列提示、戰術庫（戰術名稱與說明、推薦理由、球隊總評）、評分卡片的評價、提示訊息、錯誤訊息、PWA manifest。
- 語言選擇：預設依瀏覽器語言，可以手動切換並記住；分享連結不帶語言（由開啟的人自己的設定決定）。
- 評價的句型要能依語言組字（數字、名稱放進句子的位置不同）。
- 戰術說明 `docs/PLAYS.md` 是否也出英文版：開始 M10 時再決定。
- **可驗收**：切換成英文後，所有畫面沒有殘留中文（球員暱稱等使用者輸入的除外）；繁體中文的畫面與現在相同；有測試確認兩份文字表的項目一致。

### M11：防守模式

暫緩。以下是目前的構想，都還沒有實作，開始 M11 時再確認：

- 使用者仍然操作藍隊（SPEC §1），改成**藍隊防守**：看著紅隊的進攻路線，逐分鏡畫出防守反應。
- 紅隊（系統）照劇本執行內建進攻戰術，最後一個分鏡由系統決定誰投。
- 結果：評等、預期失分、戰術評價（例如「第 3 分鏡沒有補防，禁區完全空出」）。
